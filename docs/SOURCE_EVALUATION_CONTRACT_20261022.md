## 母體、版本與時間

- S03開始前固定正式HEAD、觀察code SHA、兩個workflow指紋、plan hash、
  experiment_id、臺北D1～D7，以及實際fetch輸出的啟用source_id名冊。
  私人OPML只保存不含網址／身分的別名及入口數；私人映射留Downloads。
- 正式來源池、臺灣五站影子池、Cloudflare／Modular／Zed有限候選池、
  非新聞感測器各有分母。新候選不得混入正式精準度；反向舉證但未退場者仍納入正式池。
  期間退場時保留原母體與結果，按既有治理規範重算並列差異，不選擇性刪錯例。
- 五站×七個日曆日固定35個source-day。每日最多主／補兩slot，沿用成功／終態
  證據不算第二次成功抓取。有效空feed、缺測、來源失敗、baseline失敗分列。
- 既有collector每天回看七日，D1可能含開始前六日文章。跨日按source_id＋
  canonical URL去重，記published_at、first_seen、last_seen及每次capture版本。
  開始前已發布的文章列「起始存量」；D1～D7發布者列「觀察期文章」。兩者品質
  分開報告，只有後者能支持當期新增收益。首次看見或URL不同不等於新事件。
- 固定臺北時間及UTC原值。原始時間缺失／未帶可解析時區／未來時間均標無效；
  不以抓取時間假充發布時間。保留來源錯誤診斷，禁止以空集合代替不可讀歷史。

## 穩定性：分別評估來源與實驗

| 指標 | 明確分子／分母及門檻 |
| --- | --- |
| source-day可用率 | 該來源當天最終有valid_feed或valid_empty的日數／7；主成功、補成功另列。缺測仍在7的分母。 |
| 主試／補試成功率 | 各slot成功抓取次數／該slot實際開始的抓取次數；意圖存在但無完成證據列結果不明。另報未啟動的slot數，不能藏在成功率外。 |
| 觀察完成率 | 證據可驗且baseline合格的日數／7；程式complete可包含受限來源，不能冒充五站皆健康。 |
| baseline合格率 | schema與範圍完整、時間不晚於比較時刻且相差≤2h的日數／7；每來源沿用的舊slot／原抓取時間另列。來源抓取成功不抵消baseline缺陷。 |
| metadata有效率 | 去重文章中title、URL、published_at均有效者／全部去重文章；原始item_count是解析列數，不能當有效篇數或候選篇數。 |
| 延遲與成本 | 保留每次請求狀態、duration、redirect、抓取完成時間、runner耗時、API／artifact大小及人工分鐘；缺資料明列未知，不推估成零。 |

新來源技術准入最低條件：7日中至少6日可用、沒有連續2日不可用；
metadata有效率≥95%且至少20篇去重文章；沒有登入／付費／robots禁止或未解決
的429等限制。6/7僅為短期最低觀察條件，不表示長期可靠率達標。
只有空feed或低頻不足20篇者列證據不足；不得延長實驗湊數。
來源HTTP健康但baseline不足時可單獨報健康，不能裁決它有新增覆蓋。

## 品質與規則精準度

1. **先封存再標記。** 每站去重候選≤200篇時全查；超過時用
   `SHA256("s02-v1|" + source_id + "|" + canonical_url)`排序取前200，保存全部
   母體與選中ID。不得只挑成功案例。每站至少20個機器判為候選的去重文章，
   且涵蓋至少3個臺北發布日期，才可作來源品質准入結論。
2. 每筆標為TP（符合目前六類AI／商業事件且應收）、FP（廣編、教學、
   泛工程、列表、非AI或無具體事件等）、U（證據不足／爭議未解）。記理由、
   發布者、事件ID、原始證據連結、查核者與時間。其他錯誤可複選，不能多算文章。
3. 規則或來源候選精準度同時報`TP/(TP+FP)`、`U/N`與保守值`TP/N`，
   `N=TP+FP+U`。通過須保守值≥85%、U/N≤5%；未裁決不從分母刪掉。
   若N=0則不適用。來源樣本不足時即使100%也只列證據不足。
4. 共享分類／AI relevance／0.65閾值變更另用固定14日資料回測；
   機器判為收錄的全部去重母體≤500篇全查，超過則按上述hash法取200篇
   （使用固定字串`s02-rule-v1`）；至少60篇才可裁決規則。每個受影響來源
   額外列分層結果，不能用大來源掩蓋小來源。分層補查不混入隨機樣本主分母。
   在標記／調規則前保存獨立留出樣本；已看過的樣本只能當開發證據。
5. 對被排除文章另查漏收：每來源≤50篇全查，超過按固定`s02-reject-v1`
   hash順序取50篇。報「抽查漏收x/n」與原因；沒有完整真實事件全集，不宣稱
   這是全網recall。發現系統性漏收須修規格並另用未看樣本驗證。
6. 事實品質另查主張、官方／原始依據、轉述鏈與更正。以上85%衡量收錄規則，
   不等於真實性。存在未處置的重大錯誤、無法支持的關鍵主張或付費限制時，
   暫不准入；證據未知不能寫成造假。原創與可獨立核對的證據分開記錄。

S04另報起始存量／觀察期樣本量，避免靠歷史存量掩蓋當期低頻。
S05可裁決保留、限縮、調級、移除、准入、證據不足；任何調整仍須具體反例與
驗收案例。既有來源不足最低樣本不自動刪除，維持既有狀態並列待辦。

## 重複、增益與裁決

- baseline須對齊採樣時間並核對來源完整性，不能只看generated_at。
  現有觀察工具僅驗items schema與時間；S04另核對同期source-status／名冊與
  24h公開窗口，缺失日期不得用於「Radar沒有此事件」的結論。
- 每個事件記主體、動作／變更、發布時間與證據。不同語言／不同URL、同集團
  或同一新聞稿轉載歸同事件；新增獨立證據可有獨立增益，不能增加事件數。
- 分開報：URL重複、事件重複、已確認新增事件、既有事件的新證據、僅提早報導、
  待判定。事後baseline聯集只作後見核查，不冒充當時覆蓋；不得把candidate數
  或EVENT_REVIEW的空白裁決當已確認增益。
- 新來源除技術與品質條件外，至少有2個觀察期已確認新增事件，或2項可獨立
  核對且影響既有事件判讀的新證據，才提出准入；不足時列低增益／證據不足。
  這是本輪預先固定的最低價值門檻，來源不因符合數量而自動上線。
- Reuters／CNBC／The Information按發布者與文章證據裁決，不把Google News
  入口整體升級。Free LLM APIs另按感測器用途／健康／替代性裁決；不混入新聞品質。
- 剪減來源須列失去的已確認事件／證據及替代入口；若已證明技術不可用可裁決
  退場，但不能把零抓取稱為零新聞價值。有限候選不合格就停止，不擴大全站爬取。

## 工作負荷與停止條件

採樣最多14個slot／70個來源collector呼叫，**不是70個HTTP請求**；每次collector
有robots／首頁／feed探索／轉址，現有單次大小及逾時限制保留。SMTP每封邏輯通知
最多3次且只重試確定未接受；正常7封，異常D7可另有一次結案更正，最多8個邏輯通知。
觀察／報告／停用job分別有10／5／2分鐘上限，不能把slot數當全部runner數：
workflow_run仍可能產生跳過紀錄或多次唯讀查核，沒有實測前不得承諾總耗時。

HTTP429新增為當日終態，不在08:30自動重抓；原始probe未保存Retry-After，
此修補不宣稱支援跨日限流期限。出現持續限制須由S04停止該來源自動探測並記錄
版本／缺測，不能使用代理或換入口繞過；其餘來源的實驗期不延長。

正常自停仍需遠端結案包及其Email接受receipt，不把未知投遞當成功。
S03必須指定可執行人工停用的維護者與D7結束核查時點；最晚D8臺北08:00若未自停，
保存證據、關閉兩個實驗workflow，標「異常中止／通知未完成」。這是人工事故處置，
不會產生成功receipt、不等於自停驗收通過，也不新增監控或提醒排程。
無人接手此停止責任時不得啟用實驗。查詢超過30天保留窗會直接拒絕，不能重建
或猜測已過期的通知ledger；人工停止須在此前完成。
