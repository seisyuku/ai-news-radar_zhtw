- 正常路徑以固定輸入比較文章與事件 ID、文章修訂、事件階段與時間、來源資格、列表及選集順序、快取鍵、價格訊號和 resolver。測量耗時等非決定性欄位由 R01 列名排除。故障路徑只接受該步驗收明列的行為差異。
- Groq 第五項已結案。Groq 的工作範圍為既有快取讀取與冷卻的正確性。Gemini 摘要備援依退役裁決處理，既有讀者翻譯納入驗收。停用觀察、報告、SMTP 及私人校稿以現有離線測試和模擬服務驗證。
- 基準取自公開保存資料。回放用固定時鐘及已保存或模擬回應，生成至隔離目錄，核對 `source-status.json`。正式發布依[操作文件](OPERATIONS.md)及[專案發布規則](../AGENTS.md)執行。在各步開始時核對實際授權。已獲授權的實作可接續進行，模型建議及交接本身不構成額外審批。

## 每一步的交接

依[任務交接模板](TASK_HANDOFF_TEMPLATE.md)，開工先建立 `CHECKPOINT.md`。在長命令前後更新，記錄實際分支、起迄 SHA、既有差異、輸入版本、已驗證進度、指令與結果、待確認外部操作。每步用 Downloads 下自己的任務目錄，建議名稱 `ai-news-radar-refactor-rNN-YYYYMMDD/`，以臺北開工日命名。

每步結束或中斷都要落檔 `HANDOFF.md`，並在對話顯示下列內容。完整命令與證據放在該步目錄，專案台帳與交接摘要維護目前入口和最近十天紀錄。

1. 實際完成範圍與檔案、差異或提交，附證據位置。
2. 通過、失敗及未驗收條件，記錄測試命令、結果、樣本 SHA／時間和回復方式。
3. 下一步 ID、依賴狀態，以及可以直接執行的第一個動作。
4. **下一步建議模型與思考強度**，附一句理由。若仍有驗收或前置依賴缺口，下一步仍是當前 ID，並附具體續接動作與適用模型。模型欄為建議。

驗收及交接皆落檔時才標 `done`。中斷用 `in_progress`，有具體外部阻塞時用 `blocked`。尚未執行的步驟保留 `planned`。同一聊天可在交接後直接接續下一個已授權步驟。

## 第一階段　建立基準與故障隔離

### R01　建立可重播基準

- **依賴**　無。重新核對本機、遠端 `master`、目前 Pages 資料，以及既有未提交差異。
- **執行**　從正式生成提交挑出正常有重點、有效零則及含文章修訂或事件新階段的保存版本。至少固定一組可連續回放兩輪的資料，記錄程式 SHA、資料 SHA、臺北與 UTC 時間、政策修訂、生成入口、公開輸入及其雜湊。以現有測試或回放入口製作基準比較命令。
- **驗收**　同組輸入、時鐘及模擬回應重播兩次，比較所有決定性欄位。明列未能重現或缺少保存輸入的項目。先保存異常版本值、異常健康計數、未來拒絕時間及重複導言的失敗案例。
- **交接**　快照清冊、比較命令、基準結果、待修案例與保存材料的限制。
- **下一步 R02**　**GPT-6.2 Sol／High**。載入已固定的壞值案例，先重現它對生成入口的影響。

### R02　隔離壞快取與壞健康紀錄

- **依賴**　R01。
- **執行**　驗證翻譯及 Groq 快取版本與容器格式，按既有用途捨棄可再生的壞紀錄。將來源健康舊格式正規化放在載入或轉移入口，按 `(site_id, source_id)` 隔離壞值。
- **驗收**　合法舊格式維持既有結果。版本字串、錯誤型別、缺欄和局部壞列經生成入口可完成快照。驗「失敗兩次 → 跳過 → 再失敗 → 成功」，並確認群組跳過時保存子來源狀態、不同 ID 各自計數。損壞的 archive 依其原契約停止。
- **交接**　逐類壞資料的處理結果、兩輪連敗轉移測試、可再生資料的故障隔離範圍。
- **下一步 R03**　**GPT-6.2 Sol／High**。用固定時間跑翻譯與 Groq 的未來時間和到期案例。

### R03　修正冷卻、重試邊界及導言配額

- **依賴**　R02。
- **執行**　依輪次時鐘判定拒絕項的有效時間，讓未來時間的拒絕項視為無效。導言在同輪記住已嘗試 URL。用假單調時鐘驗收翻譯、供應商重試和導言預算。
- **驗收**　驗剛建立、到期前、恰好到期及未來時間。翻譯 429、標題一次修復及延後修復、Groq 的內容補試與 JSON 回退維持原有語意。六筆相同失敗 URL 只花一次導言嘗試，其後另一有效 URL 能抓取，且失敗 URL 下輪可再試。一般 HTTP 退避以模擬回應驗證。
- **交接**　各模組時鐘用途、時間邊界及重複 URL 回歸結果。
- **下一步 R04**　**GPT-6.2 Sol／High**。先用有效舊價格基線驗證正常輸出，再模擬基線讀取失敗。

### R04　保護價格基線及訊號續接

- **依賴**　R03。
- **執行**　區分基線首次缺失、有效及既有檔案不可讀。暫時讀取失敗保留舊檔並將本輪價格標為降級。既有訊號仍依原窗口到期。若基線內容確實損壞，在可驗證的最後有效版本取回後續接，交接記錄恢復依據。

- **交接**　基線和訊號的前後狀態、保留的舊檔雜湊，以及恢復輪驗證。

## 第二階段　生成、發布與排程

### R05　統一封存讀取與事件歷史界線

- **依賴**　R01 至 R04。
- **執行**　從同一份 archive 讀入紀錄與生成時間，沿用現有解析器。明確化事件歷史的續用、重建與不可用結果。讓每輪固定的政策修訂、事件時鐘與測量用單調時鐘在各階段共用；保留轉換器初始化與階段計時語意。
- **驗收**　驗首次啟動、壞 archive、同 ID 再見、同 URL 取代、舊版達保留上限、AIBase 繁中晚到及 21 天淘汰。驗事件重述、實質新階段、別名合併、歷史缺失／異常／版本不支援／容量超限、有效零則與不可用。正常回放的歷史 ID、時鐘、順序和 resolver 與 R01 相符。
- **交接**　archive 單次讀取的差異、事件恢復條件、兩輪正反例及保留的舊連結樣本。
- **下一步 R06**　**GPT-6.2 Astra／XHigh**。從事件歷史寫入失敗案例開始，列出每個輸出的實際治理狀態。

### R06　對齊整輪發布狀態與清理

- **依賴**　R05。
- **執行**　先確定事件歷史寫入結果，再從同一個最終結果導出各公開檔的治理 metadata 和健康診斷。沿用單檔替換。集中標示何時可以清理 resolver，保留下一輪可續接的資料。
- **驗收**　注入事件歷史、daily、兩種 resolver、快取及最後健康檔的寫入失敗。事件歷史失敗的降級輪中，一般新聞和價格可讀，重點及雷達不可用，治理欄位同代且一致，舊 resolver 保留。其他致命寫入失敗須使 Actions 停在提交前。驗收成功下一輪的恢復與清理，並跑實際 JS 守門驗證混代讀取。
- **交接**　檔案順序及故障矩陣、每種故障的可見結果、恢復與清理條件。
- **下一步 R07**　**GPT-6.2 Astra／XHigh**。在兩份本機 clone 中重現事件歷史相同、其他生成輸入已前進的推送競態。

### R07　保護並行快照與 Git 發布

- **依賴**　R06。
- **執行**　以生成前的 Git 基準決定產物是否仍可發布。推送被拒後核對會影響生成的程式、政策、設定與生成根目錄。前提已變時由新基準重新生成或交給下一個正常刷新，只有可證明不影響生成的並行變更才續用產物。沿用有界重試和 Git 一般快轉保護。
- **驗收**　用本機 bare remote 及兩份 clone 跑實際發布路徑。逐項驗事件檔新增或刪除、僅 archive 或市場狀態前進、生成程式或政策前進、文件並行提交、二次競態、無差異及重試耗盡。保留所有並行提交與較新資料。
- **交接**　基準範圍與判據、命令和雙 clone 圖譜、可重試與應重生成的分支。
- **下一步 R08**　**GPT-6.2 Sol／High**。從成功但跳過更新的 heartbeat run 入手，重播排程邊界。

### R08　驗證 heartbeat 與 watchdog 的判據

- **依賴**　R07。
- **執行**　用保存或模擬的 Actions 資料分辨「workflow 成功」「更新 job 成功」與「公開快照前進」。驗證成功的空跑是否會延後下一次有效刷新。若證實，調整 heartbeat 使用可證明更新的訊號並驗證 API 失敗和無歷史行為。保留既有觸發路徑與 25／90 分鐘設定。
- **驗收**　測無歷史、API 失敗、24／25／26 與 89／90／91 分鐘、整分鐘取整、成功但跳過、排程失敗、手動與 watchdog 代觸發，以及併發中的刷新。使用模擬 API 完成測試。
- **交接**　兩個判據、空跑的重現證據及結果、邊界測試和工作流差異。
- **下一步 R09**　**GPT-6.2 Astra／High**。拿 R06 的健康及降級資料，改變輔助檔抵達順序並記錄治理結果。
