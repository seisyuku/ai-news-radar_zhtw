## 若將來重評，採用的對齊與品質契約

1. 將供應商、完整系列／版本與變體（例如 Flash、Pro、尺寸及 preview）組成候選模型鍵；只做 Unicode／大小寫／標點的可重現正規化。結構化 ID 須在相同供應商命名空間完全相符。媒體文字須有明確供應商及完整版本佐證；搜尋查詢名稱、泛稱或只有型號片段時標為 `unknown`，不強行合併。
2. 每則證據另標 `release`、`eval`、`price_api`、`deployment`、`commercial_adoption`、`safety`，保留原文連結、時間、發布者及「已宣布／已上線／預告／傳聞」狀態。報導、官方公告和追蹤資料維持不同證據等級；不得把價格目錄的相近名稱或多篇媒體數量當成相同模型的驗證票。
3. 將來若評估七日模型生命週期，以凍結的輸入版本、時間窗及人工判定表重跑；按模型鍵和階段記錄可對齊、歧義、錯併、漏併及首次報導延遲。以官方發布／價格／API 原始材料建立參考集合，分來源與階段報告 precision、漏報及成本，並將無法判定者單列。七日是離線模型階段評估窗，**不改網站 24 小時規則**。
