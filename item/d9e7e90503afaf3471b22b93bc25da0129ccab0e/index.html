Title
Amazon Redshift 支持通过与 Amazon S3 表类数据存储服务集成来长期保留系统表
Source
AWS News
Published
2026-08-20T15:00:00Z
Summary
Amazon Redshift 现已支持通过与 Amazon S3 表类数据存储服务 集成，长期保留系统表数据。 借助此功能，您可以将 Redshift 系统表数据留存期配置为超过当前 7 天上限，以满足合规性、审计和可观测性要求。启用此功能后，AWS 会自动以 Apache Iceberg 格式 将系统表数据写入 S3 表类数据存储服务，并管理分区、压缩和留存。 客户使用 Redshift 系统表来监控查询性能、审计数据仓库活动并满足合规要求。以前，延长留存期需要构建并维护自定义提取、转换、加载（ETL）管道来复制系统表数据，这会增加开发工作量和持续运营开销。运营多个数据仓库的客户过去面临额外的复杂度，需要依靠 Redshift 数据共享功能，将各个仓库的系统表数据汇总到一处以进行跨仓库分析。此功能支持系统表数据的自动复制，无需使用自定义 ETL 管道，也不会与生产工作负载产生资源争用。 如果您运营多个数据仓库，则可以将其系统表数据整合到一个位置，以实现跨仓库的可观测性和分析。由于数据采用开放的 Apache Iceberg 格式存储，您可通过 Redshift、 Amazon Athena 或任意兼容 Iceberg 的引擎查询数据，还能借助 AWS 服务或第三方工具构建可观测性控制面板，而不会产生额外运维开销。此外，可通过 AWS Agent Toolkit 查询系统表数据，从而获得性能洞察和优化建议。 此功能适用于以下 AWS 区域内的 Amazon Redshift Provisioned RG 和 RA3 实例以及 Amazon Redshift Serverless ：美国东部（弗吉尼亚州北部）、美国东部（俄亥俄州）、美国西部（北加利福尼亚）、美国西部（俄勒冈州）、非洲（开普敦）、亚太地区（香港）、亚太地区（台北)、亚太地区（东京)、亚太地区（首尔）、亚太地区（大阪）、亚太地区（孟买）、亚太地区（海得拉巴）、亚太地区（新加坡）、亚太地区（悉尼）、亚太地区（雅加达）、亚太地区（墨尔本）、亚太地区（马来西亚）、亚太地区（泰国）、加拿大（中部）、欧洲地区（法兰克福）、欧洲地区（苏黎世）、欧洲地区（斯德哥尔摩）、欧洲地区（米兰）、欧洲地区（西班牙）、欧洲地区（爱尔兰）、欧洲地区（伦敦）、欧洲地区（巴黎）、以色列（特拉维夫）和南美洲（圣保罗）。要了解更多信息，请访问我们的 文档 或阅读 博客 。
